# GPS-трекер: ConCox GT02 + Telegram-бот

Сервер GPS-трекинга на .NET: принимает координаты от трекера **ConCox GT02** по TCP,
пишет их в **SQLite** и показывает их в **Telegram-боте** — текущая позиция на карте
и трек за период, отрисованный линиями, цвет которых зависит от скорости.

> 🤖 AI-агентам: карта кода, спецификации протоколов до байта, инварианты и конвенции
> тестов — в [AGENTS.md](AGENTS.md).

## Быстрый старт

```bash
dotnet run --project src/GpsTracker     # запустить сервер + бота
dotnet test                             # 18 тестов (парсеры + интеграционные, ~4 сек)
dotnet build                            # сборка
dotnet run --project tools/MapTest      # консольная проверка рендера → *.png
```

Требуется **.NET 10 SDK**. После проверок приложение останавливают — фонового демона нет.

## Архитектура

```
TCP :5023 ──► TcpListenerService ──► SQLite (App_Data/gps-tracker.db) ◄── TelegramBotService
              (парсинг протокола)          ▲ единое хранилище           (команды, карты)
                                                                         │
                                                              MapRendererService (SkiaSharp + OSM-тайлы)
```

Worker Service с двумя фоновыми службами; SQLite — единственная связь между ними.
Трекер и бот не пересекаются: бот только читает БД.

### Поток данных

1. Трекер подключается к TCP-порту и шлёт пакеты одного из двух протоколов (см. ниже).
2. На логин сервер запоминает IMEI за TCP-сессией; локации пишутся в таблицу `GpsPoints`.
3. Бот по команде читает точки из БД и рендерит PNG по тайлам OpenStreetMap.

## Модель данных

`GpsPoint`: `Id`, `Imei`, `Latitude`, `Longitude`, `Speed` (км/ч), `Course` (градусы),
`Satellites`, `Timestamp`, `CreatedAt`. Индексы по (`Imei`, `Timestamp`) — под запросы бота.
Схема создаётся при старте приложения (файл БД в `App_Data/`, каталог создаётся сам).

## Конфигурация (appsettings.json)

| Секция | Ключи | По умолчанию |
|---|---|---|
| `ConnectionStrings` | `Default` | `Data Source=App_Data/gps-tracker.db` |
| `Tcp` | `Port` | `5023` |
| `Telegram` | `BotToken`, `AllowedChatIds[]` | токен бота, белый список chat id (кроме них бот молчит) |
| `Map` | `TileServerUrl` (`{z}/{x}/{y}.png`), `DefaultZoom`, `CachePath`, `UserAgent` | OSM, 15, `./tile-cache` |

Токен и chat id — секреты, в документацию не подставлять.

## Протоколы трекера

Протокол определяется автоматически **один раз на TCP-сессию** по первому байту:
`(` → текстовый GT02, иначе бинарный GT06. Полные байтовые спецификации обоих
протоколов — в [AGENTS.md](AGENTS.md), здесь — суть:

- **GT06 (бинарный)** — пакеты `78 78 ... 0D 0A` с CRC: логин (IMEI), локация
  (координаты, скорость, курс, спутники, время), heartbeat. На каждый пакет — ACK.
- **GT02 (текстовый)** — кадры в скобках, как шлют реальные ConCox GT02:

  ```
  (027046781654 BP05 355227046781654 260903 A 6006.9472 N 03122.7910 E 120.02 24043 ...)
   └ID          └логин └IMEI          └дата  └фикс └широта     └N/S └долгота    └E/W └км/ч └курс

  (027046781654 BR00 260903 A ...)   — BR: локация (IMEI берётся из логина сессии)
  ```

  На логин сервер отвечает `LOAD`, на локации не отвечает. Времени суток в кадре нет —
  точка фиксируется временем приёма; IMEI передаётся только в логине и привязывается
  к соединению.

## Telegram-бот

| Команда | Действие |
|---|---|
| `/start` | приветствие и список команд |
| `/pos` | последняя точка: карта с маркером + координаты, скорость, время |
| `/history` | трек за сутки |
| `/history 30m` \| `6h` \| `2d` | трек за период |
| `/history 2024-01-15 2024-01-16` | трек за диапазон дат |

Ответ приходит картинкой PNG; линия трека окрашена по скорости сегмента:

| Скорость | Цвет |
|---|---|
| < 30 км/ч | зелёный `#4CAF50` |
| 30–60 | жёлтый `#FFEB3B` |
| 60–90 | оранжевый `#FF9800` |
| 90+ | красный `#F44336` |

Карта — сетка тайлов OSM с дисковым кешем; дистанция трека считается формулой гаверсинуса.

## Тесты

`dotnet test` — 18 тестов, работают без сети и без запущенного приложения:
юнит-тесты парсеров на реальных кадрах трекера + интеграционные, поднимающие настоящий
TCP-сервер с временной БД и проверяющие записи (LOAD, ACK, точки в SQLite, битые пакеты).
Рендер карт проверяется утилитой `tools/MapTest`.

## Запуск через Docker

Локально (сборка из исходников):

```bash
./tools/generate-env.sh "<BOT_TOKEN>" <CHAT_ID>   # один раз: .env с правами 600
docker compose up -d --build                      # TCP :5023 + бот, данные в named-томах
```

`compose.yml` собирает образ из исходников; `compose.prod.yml` — для сервера: тянет
готовый образ из GHCR, исходники и Dockerfile там не нужны.

## Деплой на сервер (CI/CD)

Пайплайн [`.github/workflows/cd.yml`](.github/workflows/cd.yml), триггер — push в `main`
(и теги `v*`): тесты → сборка образа → публикация в `ghcr.io/<owner>/<repo>`
(теги `main`, `latest`, `sha-<hash>`, `vX.Y.Z`) → деплой по SSH.

### Настройка секретов

Секреты деплоя живут в **environment `production`** (Settings → Environments → production
→ Environment secrets) — там же можно включить обязательное подтверждение (reviewers)
перед деплоем. Допустимо задать их и в общих Secrets → Actions.

| Секрет | Назначение |
|---|---|
| `SSH_HOST` | IP/хост сервера |
| `SSH_USER` | пользователь, входящий в группу `docker` |
| `SSH_PRIVATE_KEY` | приватный ключ; публичная часть — в `~/.ssh/authorized_keys` сервера |
| `TELEGRAM_BOT_TOKEN` | токен Telegram-бота |
| `TELEGRAM_CHAT_ID` | chat id белого списка |
| `SSH_PORT` | *опционально*, нестандартный порт sshd (по умолчанию 22) |
| `GHCR_TOKEN` | *опционально*, PAT с `read:packages` — только если пакет GHCR приватный |

Переменная репозитория `DEPLOY_DIR` — каталог на сервере относительно `$HOME`
(по умолчанию `gps-tracker`).

`.env` на сервере создаётся **самим CI** при каждом деплое из `TELEGRAM_*` секретов
(права 600) — вручную его писать не нужно.

### Разовая подготовка сервера

```bash
# docker + compose plugin, ключ в authorized_keys — по инструкции вашего хостинга
```

Дальше каждый push в `main` обновляет сервер сам: CI пишет `.env`, делает
`docker compose pull && up -d`. Чтобы образ был доступен серверу без PAT, сделайте
пакет публичным: на GitHub — Packages → gps-tracker → Package settings →
Change visibility → Public.
